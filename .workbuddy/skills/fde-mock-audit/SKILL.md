# FDE 模拟卷审计与注入

## 何时用
- 写完一套模拟题后要自查质量
- 要把新卷子加进 `6. FDE离线版/` 离线题库

## 一、出题后的四项强制审计

按这个顺序查，**每项都要给出修订前后的数字对比**：

1. **答案位置偏斜**（最致命）
   - 单选：统计 A/B/C/D 分布，应各约 1/4。若某一项 > 40%，重排选项直到均衡。
   - 多选：统计正确项组合。若 `ABCD` 占比 > 40%，说明"选前四个"就能拿高分，必须打散。
   - 判据：把"只会选 B + 只会选前四个"的得分算出来，超过 70 分（及格线）即判废。

2. **长度泄露**
   - 量化：`len(正确项) / mean(len(干扰项)) > 1.8` 记为严重泄露。
   - **必须配合绝对差值判断**：四个选项都是短名词时（如"四种模式"）比值虚高但不是真线索。
   - 修法：精简正确项措辞（解释性内容移到解析里）+ 给干扰项补平行表述。

3. **重复选项组**
   - 检查是否有多题的选项集合完全相同。有则每题独立打乱顺序，并避免答案呈规律性字母序列。

4. **⚠️ 解析字母引用同步（最容易静默出错）**
   - 重排选项后，解析里所有 `- A 错：`、`- A/C/D 都是` 之类的字母引用必须重映射。
   - **已知坑**：行首规则和行内组合规则各匹配一次 = 映射两次（`inv²`），
     约 3/4 的字母会指错选项且**不报错**，自动检测只能抓到少数。
   - 正确写法：**单条正则、二选一分支**，一次替换：
     ```python
     PAT = re.compile(r'(^- \*{0,2})([A-E](?:/[A-E])*)'
                      r'|(?<![A-Za-z0-9/])([A-E](?:/[A-E])+)(?![A-Za-z0-9/])', re.M)
     ```
   - 更稳妥：把"用字母点名选项"改成"用内容点名选项"，如
     `**C（工作流）和 E（插件）不在…**` → `**「工作流」和「插件」不在…**`。
   - 断言：① 替换前后引用组数量相等；② 被判"错"的字母组不得包含正确答案字母。

## 二、事实核查：用脚本回原文比对，别派子代理通读

四份课程材料共约 382KB。**派子代理通读会超时（1200s 无响应）**。
改用 Python 拿关键词回原文抓上下文，重点核对数字、阈值、互斥规则：

```python
keys = ["最小执行间隔","20 字","最多不超过 5","4800","80 个","120 秒",
        "仅支持标准模式","不会相互继承","按行解析","边界与验收","身份映射","人工兜底"]
```
已核对通过的高频断言：定时任务最小间隔 1 小时；评测任务名称 20 字且不可重复、评测集最多 5 个且列名须一致；
切片最大长度 4800 字符（重叠 10%、最高 25%）；向量模型上传文档后不可变更、需清空才可改；
Claw 最多 80 个 Skills；微信二维码 120 秒且一个微信号只能绑一个工作台；
对比评测**仅支持标准模式**且多模型最多 2 组；设置兜底回复**必须关闭联网搜索**；
模式切换时知识库与工作流范围不变，但提示词、模型配置**不继承**。

## 三、注入离线版（新增一套）

数据契约（`bank.js`）：
- 每套 60 题（40 单选 + 20 多选），**单选 1.5 分、多选 2 分**，满分 100，70 分及格。
- 每题必含字段：category / type / points / stem / options / answer(索引数组) /
  explanation / sources / topics / conceptIds / atomIds / authoredKey / cardId / facet /
  paper / number / id（`FDE-{套:02d}-{序号:02d}`）。
- 前 20 套 blueprint：ai 4+2 / position 2+2 / core 12+2 / design 10+5 / industry 6+3 / delivery 2+4 / security 4+2。
  blueprint **前端不使用**，新套按考纲比例 2:1 分配即可，无需强行对齐。

**bank.js 绝不修改**（使用说明承诺与原站 MD5 一致）。做法：
1. 新建 `bank-extra.js`，内容是把新题 concat 进 `B.questions` 并合并 `B.sources`；
2. 入口页把它插在 `bank.js` 之后、`core.js` 之前。

**必须同时放开三处写死的"20 套"上限**，否则新套不可用：
- `core.js` → `validSession` 里的 `paperId>20`
- `app.js` → 首页 `Array.from({length:20})`、`20 套独立试卷`、`1,200 道模拟试题`、`done / 20`
- `app.js` → `mergeHistory` 里的 `paperId<=20`
改成从 `B.questions` 推导（如 `const PAPER_COUNT=Math.max(0,...B.questions.map(q=>q.paper));`），一劳永逸。

课程依据锚点：`sec-{章}` 或 `sec-{章}-{节}`（见 `course/第N章.html`）。

## 四、验证（比开浏览器快）

```bash
node --check app.js && node --check core.js && node --check bank-extra.js
node -e "global.window={};eval(require('fs').readFileSync('bank.js','utf8'));
         eval(require('fs').readFileSync('bank-extra.js','utf8'));
         const C=require('./core.js'); /* 跑全对应得100、全错得0、validSession(新套)为true */"
python -m http.server 8099   # 再 curl 入口页，确认脚本顺序与首页文案
```
检查项：总题数 = 原 1200 + 新增；id 唯一；每套 60 题；全对 100 分；`validSession(新paper)` 为 true；
sources 全部可解析；`git diff HEAD -- bank.js` 为空（证明原题库没被碰）。

## 五、别踩的坑
- 同一文件的多处修改必须串行；跨文件才可并行。
- 改 `app.js`/`core.js` 前先 `git diff HEAD` 看有没有别人（或上一会话）的改动，别覆盖。
- 发现脚本写坏了工作区文件：先 `git show HEAD:<file>` 确认 HEAD 里有原版，再导到 /tmp 重跑，
  不要直接 `git checkout` 覆盖（可能丢掉用户未提交的手改）。
