### 为什么剔除 records/

核查过三点，结论是**剔除零代价、带着纯风险**：

1. `records/` 只是**跨机同步中转目录**（导出 → 放进去 → commit → 另一台机器导入），README 是用户自己写的，里面就有一句「⚠️ 若本仓库是 public，成绩会随 commit 公开」。
2. `app.js` **完全不读取它** —— 线上「导入记录」是 `filePicker` 让用户手动选本地文件，不 fetch 服务器上的 json。所以剔除对功能毫无影响。
3. 决策不对称：误剔除 → 重发一次（1 分钟）；误带上 → 成绩已公开且不可逆。默认保护侧。

## 11:15 修复解析 markdown 不渲染（并重发）

用户截图反馈：P21/P22 解析里 `**知识点**`、`1.`、`- A 错` 全部裸奔。

**根因**：`analysisHtml` 里 `<p>${esc(q.explanation)}</p>` —— explanation 只 esc 不转 markdown。数据侧审计（脚本 `/tmp/md-audit.mjs` 思路：全库逐题正则测 `\*\*`/行首列表）：**P21/P22 全部 120 题是 markdown 格式**，P1–P20 是纯文本（`.analysis p` 有 `white-space:pre-line`，换行本来就正常）。

**修复（渲染端一处 + CSS 两行，未动数据）**：
- `app.js` 第 3 行后加 `const mdHtml=s=>{...}`：含 md 标记（`\*\*…\*\*` 宽容星号内侧空格 / 行首 `- − •` / 行首 `\d+[.、)）]`）才走转换（空行分段 → `<p>`，连续 `N.` → `<ol>`，连续 `-` → `<ul>`，`**…**` → `<strong>`），否则原样返回 `<p>${s}</p>` → **老卷零变化**。
- `analysisHtml`：`<p>${esc(q.explanation)}</p>` → `${mdHtml(esc(q.explanation))}`。**esc 仍先于一切 HTML 生成，mdHtml 输入永远是转义后的文本**，无 XSS 回归。
- `style-theme.css` 加 `.md-body ul/ol/li` 边距。

**验证（先于发布）**：
1. `node --check app.js` 语法 OK。
2. 逐题断言脚本：1320 题 `mdHtml(esc(explanation))` —— P21/P22 无裸 `**`、走 md 路径、含结构化标签；老卷输出仍 `<p>…</p>`；无 `<script`/`onerror` 注入面。全部通过。
3. P21「发布接入与运营机制」题（即用户截图那道）抽样输出结构正确：`<strong>知识点</strong>` + `<ol>` 三步 + `<ul>` 干扰项。
